Professional Self-Assessment

Introduction

Completing the Computer Science program and assembling this ePortfolio has been a chance to look back at three years of coursework in Software Engineering and see it as a single, connected body of work rather than a list of separate assignments. The artifacts collected here, each revisited and enhanced for this capstone, represent the range of skills I've built: designing software with intention, reasoning carefully about algorithms and data structures, and managing data responsibly and securely. Together with the code review and the reflections below, they tell the story of how I think as an engineer today, and what I'm ready to bring to a professional team.

Program experience and growth

When I started the program, I had limited programming experience outside of one introductory course". Courses like Introduction to Scripting and Programming Languages pushed me to move from writing code that simply worked toward writing code that was readable, testable, and built to be changed later. By the time I reached Computer Science Capstone, I was thinking less about "does this run" and more about "will this scale, will the next developer understand it, and what happens when the input isn't what I expect."

Computer science values and skills

Across the program, a few things became central to how I approach problems:

  • Software design and engineering — writing code that is modular, documented, and built around clear separation of concerns rather than convenience. The enhancement in my Software Design & Engineering artifact
  • Algorithms and data structures — choosing the right structure and approach for the problem at hand, and being able to explain the trade-off in plain language. My Algorithms artifact
  • Databases — modeling data so it stays consistent and secure as an application grows, not just so a query works today. The Databases artifact
  • Security mindset — treating security as a constraint to design around from the start, not a feature added at the end. For example, using authenticated encryption (GCM) with a fresh IV per call to prevent tampering and IV-reuse vulnerabilities, and failing explicitly rather than falling back to an insecure default when the encryption key is missing. Databases artifact
  • Communication — writing documentation and explanations, like this portfolio itself, aimed at both technical and non-technical audiences.

How the artifacts fit together

I chose these three artifacts because they don't overlap — each one demonstrates a different layers of what a working application needs: a sound design, efficient logic, and a reliable place to store and retrieve data.

The code review that opens this portfolio walks through the original, unenhanced version of three different artifacts, so the improvement in each artifact page is visible against a concrete baseline rather than described in the abstract.

Looking ahead

This portfolio is built to do one specific job: show a hiring manager or technical interviewer what I can actually do, backed by real code rather than a list of skills on a résumé. I'm looking for a role as a Junior Software Engineer where I can keep building on the foundation this program gave me, particularly in cloud infrastructure or backend development. The discipline this capstone required reviewing old code honestly, planning enhancements deliberately, and documenting the reasoning behind every change, is the same discipline I plan to bring to every project after this one.
